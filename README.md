# 今天吃什麼

依搜尋位置找附近餐廳的繁體中文行動網頁，支援隨機分類、直接抽選店家、收藏與步行路線。

## 功能

- **步行範圍**：可選約 5／10／15／20 分鐘，對應 400／800／1,200／1,600 公尺半徑。距離以直線計算，步行時間是估算值，實際路線以 Google Maps 為準。
- **營業篩選**：勾選「只看營業中」後，僅保留 Google Places 回報為營業中的店家；營業狀態不明的數量會另外提示。
- **分類選擇**：上下滑動分類輪盤、點擊開啟選單，或使用右側隨機分類按鈕。分類可新增與刪除，至少保留三個。
- **幫我決定一家**：從目前分類、範圍與營業篩選的結果中抽選店家。尚未搜尋時會先搜尋目前分類；按「換一家」再次抽選。優先避開最近五家，候選不足時允許重複，且在有其他候選時避開剛抽中的店。
- **收藏**：按餐廳旁的「收藏」，在「收藏」分頁查看或取消，最多儲存 100 間。
- **最近選過**：保留最近 20 間抽中的店與最後抽選時間，同一家店只保留最新紀錄。這不是用餐或到訪紀錄。
- **手動位置**：展開「手動設定搜尋位置」，輸入地址或地點並選擇候選結果；也可輸入 `25.0478,121.5170` 這類緯度、經度座標。重新定位按鈕可切回裝置位置。
- **步行路線**：點餐廳名稱展開連結，或從抽選結果直接開啟 Google Maps 步行路線。起點是目前設定的搜尋中心，也可另外查看店家資訊。

收藏與最近選過的清單不套用附近的步行範圍或營業篩選。儲存的店家不保留即時評分或營業狀態，請開啟 Google Maps 確認最新資訊。

## 資料與定位

自訂分類、收藏、抽選紀錄與位置快取存於瀏覽器本機儲存空間，不提供帳號或跨裝置同步。清除瀏覽器資料會移除這些設定；裝置拒絕儲存時，操作僅保留於本次開啟期間。

位置快取最長使用 30 分鐘。裝置定位的快取會在背景更新，手動位置則保留為搜尋中心，不會被背景 GPS 覆蓋。無法定位且沒有現有位置時，會明確標示並使用台北車站附近的示範位置；使用者可改為手動設定。

餐廳清單僅包含 Google Places 本次回傳、且在選定半徑內的結果，並非區域內所有店家的完整名冊。

## 目錄結構

- `index.html`：介面與瀏覽器端邏輯。
- `netlify/functions/places.js`：代理附近餐廳與手動地點搜尋，金鑰不傳至前端。
- `netlify.toml`：Netlify Functions 設定。
- `PRODUCT.md`：產品目的、使用流程與限制。
- `tests/`：使用模擬資料的前後端回歸測試。

## 部署

1. 在 Netlify 設定環境變數 `GOOGLE_API_KEY`。
2. 金鑰所屬專案須能使用 Google Places API 的 Nearby Search (Legacy) 與 Text Search (Legacy)。既有餐廳搜尋使用前者，新增的地址／地點搜尋使用後者。請確認金鑰限制允許伺服器端請求。
3. 將專案部署至 Netlify，使用 HTTPS 開啟網站以取得裝置定位。
4. 測試定位、附近餐廳搜尋與手動地址搜尋。輸入座標不需要呼叫地點搜尋 API。

未設定金鑰時，函式會回傳 `Missing API key`。餐廳搜尋及地址搜尋需要網路連線。

## 本地開發與測試

```bash
npm install -g netlify-cli
netlify dev
```

使用 Netlify CLI 提供的本機網址測試完整流程；單純開啟 HTML 或使用靜態伺服器無法執行 Netlify Functions。

以 Node.js 內建工具執行回歸測試：

```bash
node --test tests/*.test.cjs
```

測試使用模擬資料，不呼叫 Google Places API，也不讀取真實 API 金鑰。它們無法驗證線上金鑰權限、即時營業狀態或真實路線時間。

## 加入主畫面

專案包含 Web App Manifest 與獨立顯示設定，可透過支援的瀏覽器選單加入主畫面。目前未實作 Service Worker 離線快取；加入主畫面不代表餐廳搜尋可離線使用。
